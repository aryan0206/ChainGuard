# H6–H9 readiness matrix for frozen live case IDs

Source of case IDs and expectations: `../H2-H6/qualification_plan.json`. This is a capability/readiness assessment, not executed data. All cases remain **BLOCKED**. Common entry blocker `G`: unmodified `M6Host.open_task` invokes Git at configuration generation/validation; no no-Git entry point is supported. `S`: no independently retained source/handler/sink raw stream with complete-capture closure. `C`: no assessor-held control/reservation receipt from the confirmed COMMIT boundary. `B`: sink supplies destination and byte count only, not actual bytes/digest. `T`: no independently specified and retained task-outcome collector. `F`: no predeclared qualified fault hook/observer for this case. Current interfaces are engineering capabilities, not H6–H9 witnesses.

For clean eligible cases, READY also requires an assessor-generated run challenge, independently pinned configuration and signer key, clean-close package export, and offline verifier report. A valid signed package is corroborating evidence, never a substitute for the listed external witnesses. The planned M6Q set does not yet cover every final M6 contract: multi-scope all-or-nothing, dispatched failure/no-refund, and ambiguous outcome still require separate frozen qualification cases before claiming final M6.
