# E09 exact variant map

The mechanism descriptions are from the frozen [protocol](../../docs/EVALUATION_PROTOCOL.md), [Architecture Lock](../../docs/ARCHITECTURE_LOCK.md) and [saved preparation plan](../completion_sprint_2026-11-02/FIVE_HOUR_SPRINT/e09_variant_and_mutation_plan.json). They are **not newly frozen case-level expected outputs**. See [readiness](E09_PARITY_READINESS.md), [results](E09_PARITY_RESULTS.md), [evidence audit](E09_EVIDENCE_AUDIT.md), and [status](E09_FINAL_STATUS.md).

| Variant | Frozen mechanism / expected behavior boundary | Existing evidence | Missing parity work | New check executable now? |
| --- | --- | --- | --- | --- |
| **A0** | Structured records with no evidence integrity; no hash authentication claim | Protocol/plan label only | Equal semantic input, harness, byte vectors, mutation cells and predeclared expected dimensions; cannot claim tamper detection | **NO** |
| **A1** | Independent event hashes; authentication claim requires separately retained trusted digest | Protocol/plan label only | Hash-only harness, assessor-held trusted digest condition, same-content input and mutation expectations | **NO** |
| **A2** | Unkeyed event hash chain, recomputable without trusted closure | Protocol/plan label only | Chain harness, trusted-reference condition, recomputation controls, byte vectors and expected dimensions | **NO** |
| **A3** | Signed canonical event chain, P-256/SHA-256, pinned signer and context; structural rejection and commitment rejection are separate dimensions | Five retained development cells with raw packages/verifier reports; 3/5 expected dimensions matched | Resolve/explain two **unchanged** dimension mismatches and freeze full research mutation ledger; do not relabel schema rejection as commitment failure | **Existing only**; no new frozen case |
| **A3T** | Signed ordered canonical transcript; same semantic envelopes/closure, **without unused event-chain computation** | Lock specifies design; no retained transcript package | Implement/test transcript schema, domain-separated bytes, signed closure, vectors and equal-content comparison; freeze cases | **NO** |
| **A4** | A3 plus independent expected run and durable fresh whole-run acceptance | General M5/M6 engineering acceptance evidence, not E09 parity cells | Freeze E09 acceptance/mutation cases, independent inventory and registry-boundary oracle; equal A3 content and evidence | **NO** for E09 parity |
| **A4T** | A3T under same independent expectation and durable acceptance wrapper | Lock specifies design; no retained A4T package | A3T implementation plus A4T acceptance format/vectors/cases and parity controls | **NO** |

The full E09 contract additionally calls for edit, insert, delete, duplicate, reorder, splice, truncate, whole-session removal, recompute, pre/post-seal, wrong key/context/identity and policy/detector substitution classes, with predeclared per-dimension outcomes. The preparation plan lists a subset to freeze, not a complete cell ledger. Signed formats must share semantic content, durability, signature frequency, ECDSA P-256/SHA-256 pins and verification obligations; A3T/A4T cannot secretly pay the cost of the unused chain. No missing row in this matrix is counted as an executed check or an exclusion.
